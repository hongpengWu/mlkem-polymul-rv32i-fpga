## 恢复时的工作

当前原始 `run.py` 从头运行全套，尚无续跑参数，恢复时不要直接执行它而覆盖本次记录。
下次由代理先添加按剩余用例生成批次的入口，然后再启动仿真：

1. 校验已保存 CSV 与快照 SHA-256，并逐行对应官方 case 身份。
2. 保持同一固件和 CPU/内存配置，只从官方 fixture 提取各组剩余输入与预期结果。
3. 通用固件已接受 1..145 项；新批次将本地 index 从 0 编号，另存与原始 index 的映射。
   TB 需要允许批次长度，且仍严格检查每例结果；保留本次原 TB 快照，不能修改历史来源记录。
4. 每次新批次单独归档日志和输入身份，不覆盖本目录；完成后合并原始身份、检查无重复/遗漏，
   三组最终各 145 项才认定完整通过。
5. 汇总器当前要求一个完整 145 例日志；恢复时扩展为验证多个批次，再统计全部真实结果，
   不人工拼接或伪造一个仿真 PASS。
